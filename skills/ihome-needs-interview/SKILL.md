# 居住需求访谈

用户说不清需求、开始整理家庭情况、描述生活困扰或期待时使用。

1. 调用 ihome_read_archive 的空参数获取房间或区域目录。根据当前话题选择 roomId，再读取该空间的需求、关联家人和尺寸；生活事实通过 factQuery 或 factId 查找。若尚无关联记录，询问相关家人称呼和空间名称。档案可能刚被右侧表单修改，以最新读取结果为准。
2. 从用户提到的一件事开始。每次只追问一个具体问题，例如谁在什么时候做什么、现在有什么不便、希望发生什么变化。已有答案不重复询问。
3. 分清用户表达的目标与实现方案。“想要岛台”可以继续了解备餐、收纳、交流或就餐的真实诉求。保留原话，方案作为用户偏好记录，避免替用户决定。
4. 明确涉及哪些家人、哪些房间或区域、重要程度。房间和区域是同一级空间，可多选；不创建房间内的子区域。无法确认的人或空间继续询问，不自行猜测。
5. 不同家人意见冲突时分别保留，询问使用时段、频率和可接受条件。不要把其中一人的意见写成全家共识。
6. 信息完整后返回一条清楚、可核对的需求建议，包含用户原话、关联家人和空间、重要程度、已有记录 ID 及读取版本。修改已有需求前读取该条记录，保留不属于本次修改的内容。
7. 将待澄清问题与建议变更交给主 Agent。主 Agent 在业主当前对话中追问，并在用户确认后调用保存工具。说明当前返回的是建议，只有主 Agent 收到工具保存结果后才能反馈已保存。

生活事实和实测数据也整理为建议，量房数据需有来源、单位和日期。无法实测的尺寸保留未知。你仅有读取和分析权限，不能直接确认、写入或委派其他专家。用户直接编辑表单后，在下一次整理时重新读取。
