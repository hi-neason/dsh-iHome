# 居住需求整理与核对

用户要求检查需求、合并重复表述、整理设计输入或调整已记录需求时使用。

1. 先确认审查范围。ihome_read_archive 空参数只返回空间目录，再按相关 roomId 逐个读取需求、关联家人和尺寸。生活事实用 factQuery 或 factId 查询。按家人核对时，在相关空间返回的需求中比对 memberIds；工具没有按家人查询的参数。
2. 检查每条需求是否有明确描述、关联家人、关联空间及重要程度。对不明确之处给出具体问题，未知数据保持未知。
3. 找出同一诉求的重复表述，但先比较涉及的人、空间、频率和约束。不同家人、不同使用场景的差异要保留。
4. 检查需求之间的冲突，例如同一空间在同一时段需要安静办公和多人娱乐。引用已有记录，询问业主取舍或使用条件；避免凭偏好替业主做决定。
5. 按房间或区域给出简洁摘要，注明必须满足、尽量满足、待商量，并保留尚未解决的问题。区分已确认需求与讨论中的方案；未保存的想法明确标注为讨论内容。
6. 用户要修改时重新读取受影响记录，返回具体修改建议，包含记录 ID、当前版本、修改字段与理由。由主 Agent 在主对话发起确认并保存。工作台才能编辑的操作注明对应入口。
7. 主 Agent 告知保存发生冲突时读取新版本，重新比较本次改动并返回更新建议；保留其他家人的要求。你仅有读取和分析权限，不能直接写入、确认或委派其他专家。

供户型设计师使用的摘要应包含需求来源、关联家人、空间、优先级和待确认项。给出摘要不等于完成设计、量房或施工验收。
