# iHome

iHome 是面向智能装修与家居的 DeepSeek Harness 插件。首页可以按装修阶段选择专家，点击角色头像即可打开对话和工作台。设计阶段可以咨询需求分析师、户型设计师和风水大师，选商阶段由选商核价分析师负责，施工阶段由选材采购买手和施工项目经理负责，验收、入住阶段分别由验收监理和入住规划师负责。装修知识助手、文档资料员、任务待办助理和财务经费专员在所有阶段均可使用。界面跟随系统明暗外观，首页使用随插件打包的 Three.js 绘制微缩装修工作室。十二位专家各有岗位和动作，点击场景中的人物或下方名片可打开相应工作台。动画支持暂停并遵循系统减少动态效果设置，无法启动 WebGL 时显示工作室静态图。开发基准为桌面端 `0.2.2-rc.5`。

## 从源码构建

在仓库根目录使用 Node.js 22.14 或更新的 22.x 版本和 npm 构建、验证插件。

```sh
npm ci
npm test
npm run build
```

构建会先检查 TypeScript 类型，再将宿主和客户端入口输出到 `dist/`。React 由桌面端提供。

## 在桌面端加载

1. 构建完成后，在仓库根目录运行 `pwd`，复制仓库的绝对路径。安装目录应包含 `package.json`。
2. 在 DeepSeek Harness 打开 **插件 → 添加插件 → 安装第三方插件**，将路径粘贴到「包名或地址」，确认安装。
3. 在「已安装」中打开 **iHome**，确认组件显示「运行中」。本地开发更新宿主接口或 Agent 预设后，重新构建插件，完整退出并重新打开 DeepSeek Harness，以便桌面端加载新版宿主。

点击左侧 **iHome** 回到装修专家团首页。首次打开时，插件会将 `~/iHome工作区` 注册为 **iHome工作区**。从首页点专家名片，或在右侧工作台点「切换专家」，都可以在当前 iHome 主会话里使用所选专家的工作台。例如，在同一个厨房装修话题里，可以依次查看家庭需求、选材和待办。

要另起话题，在 iHome 工作区使用 DSH 的「新会话」。从其他工作区进入时，iHome 可以继续上次使用的有效 iHome 主会话。首次进入、当前或上次会话已归档且没有可继续的当前会话时，iHome 会新建对话。已归档的会话由你在 DSH 中手动恢复。

在桌面宽屏上，中间是 DeepSeek 原生对话，右侧是该专家的 iHome 工作台。可拖动分隔线调整宽度，或收起右栏。也可从右栏的工具目录打开 iHome 工作台。在工作台点击「带到对话」等操作，会把相关内容追加到当前会话的输入框，由你编辑并发送。

## 在同一会话使用专家团

iHome 在 DSH 模式菜单中提供一个「iHome专家团」。直接描述问题，主 Agent 会按需委派需求分析师、户型设计师、风水大师、选商核价分析师、财务经费专员和任务待办助理。可以先整理家人的需求，再请设计师调整布局，最后把待量的尺寸交给任务助理。涉及档案、设计、选商、记账或任务修改时，当前对话会展示具体变更，业主接受后写入本机。

要直接点名，在 **iHome工作区** 的主会话输入框中输入 `/`，从「iHome专家团」分组选择专家，补上问题后发送。例如：

- `/需求分析师 爸妈偶尔留宿，书房平时还要办公，该优先考虑什么？`
- `/户型设计师 复制当前方案，把书桌移到窗边，让书房也能留宿。切换前后两个方案给我看。`
- `/选商核价分析师 对比两份半包报价，哪些项目可以直接比较，哪些要请商家书面说明？`
- `/任务待办助理 根据刚才讨论的书房安排，整理一份量房待办。`

点名只作用于这条消息。标准模式也可以在 iHome 工作区点名专家。在 **设置 → iHome** 中可以分别配置专家团和六位专家的提示词与技能。主 Agent 的设置在下一轮生效，子专家采用下一次委派时的设置。

旧版创建的专家会话仍可从 DSH 的会话历史或归档中找到。打开任意一条活动 iHome 主会话，都能在其中切换专家。历史消息、会话标题和模式随原会话保留。

## 选商核价分析师

从首页「选商阶段」打开「选商核价分析师」。在「公司档案」登记一家装修公司，进入详情即可上传和重读这家公司的各版设计图、报价、合同与其他原件。旧版本可展开查看和下载。错误或作废的原件可停用并恢复；公司退出候选后仍可在「已退出」中回看资料或恢复候选。

- **网上评价**按公司、城市和门店调研。将请求带到对话并发送后，分析师查阅公开网页，列出原文、归属依据和样本局限，确认后存回公司档案。
- **公司审核**可勾选一家公司要审的资料版本。报告交叉核对图纸、报价和合同，给出带出处的发现、价格依据和可直接问商家的问题。
- **公司对比**可选择多家及各自版本。没有报价、合同或评价的公司也可以参加。工作台展示比较范围与可比金额，专家团在对话中返回逐家分析，确认后可回看当时的报告。
- **报价工具**支持录入分项、同口径比价、参照单价、合同澄清及选商决定。商家复报价可另存新版本。

## 户型设计师

从首页的 **设计阶段 → 户型设计师** 打开方案列表。点击方案名称进入预览。要尝试另一种布局，可以先复制方案，再在副本中继续对话。

在 DSH 会话里附一张户型图，或直接描述房屋布局。例如，附图后发送「按这张图建一楼，保留厨房和阳台之间的门」。支持图像输入的模型可以从普通图片起步。尺寸看不清时，设计师会说明草模采用的估算值，后续可以用实测数据修正。

户型设计师按楼层生成和修改 Three.js 源码。主会话展示变更，接受后保存到本机，右侧画布自动更新。随后可以接着说「客厅北墙缩短 40 厘米」或「结合家人的需求，评审一下这个布局」。平面图和 3D 立体图共用模型，可平移、缩放，并可在立体图中旋转、查看整栋或单层。点击 **撤销上次修改** 可恢复该方案上一次的模型。

方案列表还提供文件交换。

| 文件 | 用途 |
| --- | --- |
| `.ihome.json` | 保存方案名称、可继续修改的楼层源码及所引用的本地素材。兼容已有的墙、门窗、家具与已校准底图。 |
| `.glb` | 将已有的自包含模型导入为独立方案，或导出整栋几何给其他三维查看器。 |

## 家庭档案

打开 **需求分析师 → 居住需求**。可以直接记下一条需求，在同一张表单中添加家人和「房间或区域」，也可以从一件生活里的烦恼开始对话。每条正式需求至少关联一位家人和一个房间或区域，可关联多个空间，也可按任一空间筛选。AI 整理需求、生活事实或量房尺寸后，会在当前对话列出改动。选择「接受」即保存到本机，工作台自动刷新；选择「不接受」或填写修改意见可继续讨论。已入档的单条需求可以带入设计与选材讨论。

**居住需求** 页分为「需求」和「决定」两个标签。「需求」展示居住需求表和筛选条件。「决定」展示选定的做法、关联需求、选择理由和依据资料。更新决定时会保留旧版本，可回看当时的取舍。

**家人与房屋** 分为「家人」「房间或区域」。家人表可填写称呼、性别、年龄、居住时间和居住需求，超过 20 字的需求可展开查看全文。书房、玄关、阅读区等空间都可以直接添加。每个空间占一行，列出关联需求和家人。旧档案中记录在子区域的需求会自动归到所属房间。已有生活资料和尺寸可分别在对应表格下方展开查看。团队共用这份家庭档案。

数据通过 DSH 宿主的 `storageDomain` 保存在本机。默认 JSON 后端的档案域是 `ihome_archive`，附件由宿主保留原件。手动录入、查找和导入资料均可离线使用。AI 对话使用 DSH 已配置的模型，家庭档案的读取和提案工具仅在 **iHome工作区** 的会话中启用。

在 **需求分析师 → 基础资料** 可以保存原始户型图、量房资料、交付照片与物业规定。基础资料也会出现在 **通用助手 → 文档资料员**。旧档案中未分类的附件按原始资料显示。

文档资料员的工作台支持将本机文件按装修阶段归档，区分文档和物料资料，填写来源、备注并关联房间或区域。可以搜索、编辑或下载原件，也可以在对话中按关键词、阶段或类型查找归档记录。对话检索返回资料名称等归档信息，需要阅读正文时请提供原件。

## 业主待办

打开 **通用助手 → 任务待办助理**，可以记下待办、填写备注和计划日期。日期可以留空，之后从「未排期」找到任务再安排。月历标出每天的任务数，点击日期可查看当天的清单。勾选任务即可标记完成，再点一次可重新打开。工作台显示整体完成进度和已逾期的待办数量。

也可以在专家团会话中说「周六去现场确认厨房插座位置」，或问「这周还有哪些事没做」。任务待办助理可以查询已保存的任务。新增、改期、完成或删除操作均在当前对话中确认。任务保存在本机的 `ihome_tasks` 数据域。

## 财务经费专员

从 **通用助手 → 财务经费专员** 打开装修账本。在「记一笔」中描述实际发生的付款或退款，点击「带到对话」并发送。也可以直接说 `/财务经费专员 今天付给设计工作室 800 元设计定金，请记在设计阶段。` 核对日期、用途、阶段与金额，接受后流水会保存在本机。金额按人民币元显示，精确到分。

选择「全部阶段」或一个装修阶段，可以查看付款、退款、净支出与流水明细。「分析支出」用于查看钱花在了哪里，「规划预算与待付款」可以结合报价和合同讨论后续开销。

## 风水大师

从 **设计阶段 → 风水大师** 可以看户型风水，也可以比较两种家具摆法。例如，发送 `/风水大师 家人在意开门见厅。请结合这张户型图，比较玄关设屏风和调整沙发位置的做法。` 可附图、使用当前户型方案，或直接描述门窗和家具的位置。专家会解释传统讲究，并结合采光、隐私和通行空间提出选择。若要按方位讨论，请注明图上的指北方向。

## 开发入口

| 文件 | 用途 |
| --- | --- |
| `package.json` | 声明包名 `dsh-ihome`、兼容版本范围和组合包入口 |
| `cordis.patch.yml` | 将组件 `ihome` 加入宿主配置 |
| `src/index.ts` | 宿主插件的 Cordis 生命周期入口，注册本地档案接口和 AI 工具 |
| `src/ihome-workspace.ts` | 专用工作区、活动会话选择及工作台上下文 |
| `src/client.tsx`、`src/ModuleWorkbench.tsx` | 首页入口、原生会话导航、右侧工作台与对话草稿 |
| `src/Home.tsx`、`src/ExpertExhibit.tsx` | 首页导航、住宅主视觉与动效 |
| `src/modules.ts`、`src/ModuleDetail.tsx` | 角色与阶段目录、准备清单和对话入口 |
| `src/DesignWorkbench.tsx`、`src/design-model.ts` | 户型设计工作台和共享模型 |
| `src/Knowledge.tsx` | 装修知识指南 |
| `scripts/build.mjs` | 将 TSX 打包为桌面端模块加载器使用的客户端格式 |
| `locale/en.json`、`locale/zh.json` | 设置插件管理页的英文和中文名称与简介 |
